# 分时“数据暂缺·重试中”全链路走查

日期：2026-10-15，北京时间。范围：待发版源码，不代表已安装应用或线上资产包含修复。

## 结论

此前有分时失败、重试节奏、锁隔离、队列和诊断的分项测试，但未覆盖整条链路的日期传递、同点集恢复重绘、首次重试和跨股票消息交错。
本次确认并修复了下表中的问题，新增 24 项专项测试；用户已确认的标签样式与分时无遮罩保持不变。

## 已确认问题与修复

| 等级 | 问题 | 原影响 | 修复与证据 |
| --- | --- | --- | --- |
| P1 | 分时源交易日未带到 UI | 非交易时段取得的昨日曲线被按接收日标为今天；开盘边界的晚回包可能冒充当日数据 | `MinutePoints` 保留来源交易日；UI 在交易时段拒绝已知非当日回包，未知日期仍保持未知 |
| P1 | 首屏快照混用写入日和曲线归属日 | 昨日曲线随今日行情落盘后可能被恢复为“今日曲线” | 新增独立 `minute_day`；异步写入保留元数据；盘中不预填已知旧日曲线，同日缓存也要等待实时回包确认 |
| P2 | 相同点集恢复没有请求重绘 | 状态已经恢复，但收起/无动画窗口的标签可能继续留在屏幕上 | 清除滞后态时显式标记重绘；真实 `_poll` 和标签像素验证 |
| P2 | 首次失败仍按旧周期休眠 | 收起态第一次重试虚拟实测为 5.0 秒，而非设定的 2.5 秒 | 本次睡眠立即采用更新后的重试窗口；修复后为 2.5 秒，后续耗尽仍回到正常周期 |
| P2 | 收盘或午休后滞后标签残留 | 进入非交易低频轮询后仍展示“重试中” | 会话边界清除标签并重绘；晚到的失败消息也不能重新挂上标签 |
| P2 | 无效点被当成成功 | 0/负价格、09:60 等非法时间可结束重试并污染曲线 | 两个解析器过滤非正/非有限价格和非法时间；无效均价降级；重复分钟取最后值并排序；备源多日期只保留最新一日 |
| P2 | 切股后的失败消息交错 | 旧股票失败覆盖当前股票失败，导致当前故障未显示 | 合批时先过滤股票代码；旧请求完成不复位新股票失败计数；切股重置数据龄、失败数与重试窗口 |
| P2 | 空回包的诊断口径不准确 | 盘中无数据不增加连续失败数，备用源空列表却记录“成功”并更新最后成功源 | 盘中空回包计入失败；只有非空有效回包才更新最后成功源并记录成功日志 |

## 状态与节奏

- 当日已有曲线，盘中异常或空结果：保留曲线，顶部显示标签，呼吸点冻结，不增加遮罩。
- 无当日数据或旧日数据：清空历史曲线，回到加载状态，后台继续重试；不把昨日全量画成今日进度。
- 成功返回相同或更新的有效点集：解除滞后并请求重绘，不依赖股价变化。
- 开盘前、午休、盘后：按既有非交易规则展示最近有效曲线，不常驻“重试中”。
- 快速窗口最多追加 5 次；展开态间隔取 `min(2.5, 1.0)=1.0` 秒，收起态 2.5 秒；耗尽后回到相应正常周期，不无限重开快速窗口。
- 缩 Dock 的周期仍受最小化下限约束；请求防重入仍走 `_minute_busy`，不持有主线程数据锁跑网络。
- 上述间隔是调度等待口径，实际起止间隔还包括网络耗时；不承诺故障后固定几秒内必定恢复。

## 限制与未验证项

1. 标签表示请求异常/无有效点后的恢复状态，不是独立行情新鲜度监控。源站持续返回同一天、合法但停止更新的非空点集，当前不会仅凭时间差判故障；停牌、低成交标的也可能长期没有新点，不宜任意设阈值误报。
2. 分时来源未给日期时保持未知；不能据时间字符串证明属于今天。历史旧缓存只有统一 `day` 字段，不能追溯修复原写入时已丢失的真实来源日。
3. `MINUTE_HTTP_TIMEOUT=2.0`、`MINUTE_HTTP_RETRIES=0` 不变；两源串行且每源可能走 pooled/urllib 两条路径。约 8 秒是按 socket 尝试预算推导，不是包括系统 DNS/操作系统调度在内的绝对墙钟保证。
4. `get_last_minute_source()` 是进程级“最后一次有效回包的源”，失败不清空，不等于当前在飞请求的源，也不是逐股票来源历史。
5. 没有改动已安装应用、没有发布 OTA/DMG、没有替换 `/Applications`，也没有在用户真实连接上人为断网。全量工作树有其他并行修改，必须区分本专项结果和整仓发布状态。
6. 这些是可复现的边界问题，不等于此前截图中持续重试的唯一现场根因；没有当时的诊断包和接口回包，不能反推当时主备源的实际状态。
