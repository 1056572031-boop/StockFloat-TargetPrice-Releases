# 分时 WAF 故障与价格继续更新

日期：2026-10-15，北京时间。范围：源码修复与本机在线观测，不代表安装包或 OTA 已更新。

## 现场根因

1. 本机正式应用日志在 14:19 至 14:41 反复记录分时 HTTP 501；其间穿插东财备用源成功。
2. 14:43 直接请求旧腾讯 minute 地址，生益科技和深市股票均返回 501。响应不是 JSON，
   而是跳向 `waf.tencent.com/501page.html` 的 HTML，能确认本机请求被该入口的 WAF 拒绝。
   不能仅凭此确定触发规则、服务端调整时间，或所有用户是否同时受影响。
3. 实时股价和分时走不同线程与接口。因此分时失败时，价格和涨跌幅仍可正常更新；
   旧标签“数据暂缺”却放在价格附近，没有说明只针对分时，形成全局停更的错误暗示。
4. `fetch_minute` 原先把所有主源异常累计成格式错误；两源均失败时只抛主源异常，
   顶层日志看不到备源失败原因。这使 HTTP 拦截被误报成“接口格式疑似变更”。

## 修复范围

- 默认腾讯分时入口改为腾讯 `proxy.finance.qq.com/ifzqgtimg/appstock/app/minute/query`。
  实测 JSON 与原解析器一致，保留来源交易日、累计量额均价与日期过滤；仍用 HTTPS。
- 东财备用源、现有网络超时及重试预算不变；用户显式配置的 HTTPS 地址仍然有效。
- HTTP/超时/连接失败不计入格式错误；结构与解析错误仍计入。
- 两源均失败时限流记录主源和备源错误，并保留异常链，不制造成功或清除故障状态。
- 标签改为“分时滞后·重试中”。分时滞后仍保留旧曲线并冻结呼吸点，不冻结正常行情。
- 13 个既有测试夹具和 4 个验证工具按 minute API 路径识别分时请求，避免域名迁移后返回错误类型的桩数据。

## 在线证据

`outputs/minute-waf-20261015/live-probe.json` 记录 14:48:29 至 14:48:30 的只读观测：

- 旧入口仍为 HTTP 501，保留 WAF HTML。
- 生益科技、平安银行、中芯国际各两轮，6 次全部通过新腾讯主源成功，无东财兜底。
- 每次 230 个点，来源日为 2026-10-15，09:30 至 14:48，时间有序且不重复。
- 延迟约 42 至 137 ms，保存各次响应 SHA-256。只保存摘要，不冒充保留了完整原始回包。
- 均价公式延续原实现；固定累计成交量和成交额夹具独立断言解析结果，不用线上均价作为自证。

这是小样本现场恢复证据，不是可用率统计，也不承诺新入口长期无拦截。
