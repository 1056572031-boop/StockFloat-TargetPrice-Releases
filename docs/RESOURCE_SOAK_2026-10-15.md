## 自动采集

采集脚本：`tools/resource_soak.py`。根据用户追加授权，03:00 自动启动装机版再采集；
已经在运行时不另开实例。通过 `/usr/bin/open -a /Applications/Skyrocket.app` 启动，
最多等 30 秒核实装机进程出现，启动命令返回成功但没有进程也算失败并留记录。
不主动请求摄像头权限、不切换守卫开关；产品启动后沿用用户已有设置。
独立进程只读采集，不截图、不改锁屏/休眠设置、不申请防睡眠令牌、不提权。

| 观察项 | 记录方法与限制 |
| --- | --- |
| CPU | 同一进程树累计 CPU 时间差 / 采样时间差，100% 表示一个核心；首样本、进程变化、非接电、采样缺口不算有效区间 |
| 内存 | 装机进程及子进程 RSS 的合计与变化，不冒称完整内存占用或已证明泄漏 |
| 热状态 | NSProcessInfo 的 nominal / fair / serious / critical，是系统热压力，不是摄氏温度 |
| 温度、风扇 | 当前无提权采集方式可用，明确标记未测，不把热状态换算成温度或 RPM |
| 环境干扰 | 最忙的五个进程名称与系统报告 CPU；WindowServer 等不是产品独占，不能全归给产品 |
| 无操作 | HID 输入空闲秒数，不记录键盘或鼠标内容 |
| 屏幕状态 | 锁定、主显示器休眠、产品可见窗口数量；不可见不自动认作缩至 Dock |
| 摄像头守卫 | 只读用户配置的开关，不把“配置为开”当作“实际在采集”；实际场景需用户确认 |
| 睡眠缺口 | 超过正常采样间隔 1.5 倍的缺口单列；缺口不自动认作睡眠，也不算唤醒成功 |
| 采集自身 | 采集进程 CPU 时间及每项读取失败计数 |

## 开始前条件

1. 保持接电，不需要手动打开程序；03:00 任务负责启动 `/Applications/Skyrocket.app`。
2. 机器需在 03:00 保持唤醒；采集不会自动唤醒机器或阻止睡眠，启动晚了会如实记录。
3. 关掉不必要的高负载任务，避免同时打包、跑回归或进行其他压力测试；不由工具擅自关程序。
4. 摄像头守卫按本人选择设置，不要求开启；若开启需记录开始状态，不能只看持久化开关。
5. Codex 保持运行，以便定时回看结果；系统采集本身由 launchd 启动，不依赖聊天持续执行。

## 结论纪律

先检查开始偏差、样本数量、接电比例、应用实际运行时间、采样缺口和环境干扰，
再给资源统计。没有应用运行的样本不是产品测试数据；接电观察不能作为电池续航证据。
CPU 持续偏高、RSS 持续增长或 serious/critical 热状态仅触发复核，
不能在没有对照组和真实故障证据时断言“特别耗电”“内存泄漏”或“已通过全部场景”。

本轮不打包、不安装、不发布、不推送，不修复测试期间尚未确认的推测问题。
