# 日常工作简短模板

使用方式见[日常工作入口](DAILY_WORKFLOW.md)。按任务选一个模板，只填写相关字段；
普通任务放在对话中即可，复杂任务才写本地文件。未知写“未确认/未验证”，不编造时间与结果。

## 任务确认

```text
目标/用户现象：
当前运行对象：源码 / 安装版 / 临时副本；实际版本/路径：
现有能力/历史记录：
决策：开发 / 修复 / 配置 / 诊断 / 暂缓；原因：
本次修改范围：
非目标/不能改动：
成功判据与反例：
验证档位：轻量 / 关联 / 扩大；依据：
关联测试主题/需要扩大验证的调用者：
```

## 故障定位

```text
已有缺陷 ID（已发布问题引用 quality_trend，不另建计时账）：
现象、操作顺序、实际发生时区/时刻（无原始证据则未知）：
运行身份、来源版本、源码状态与用户现场差异：
原始证据路径（脱敏，不覆盖）：
假设 → 区分假设的最小实验 → 实际结果：
已确认根因（没有证据则保持未确认）：
旧错误为何漏过，新增哪一层防线：
修复前失败/修复后通过的证据，或未能作负向验证的原因：
源码结果与仍未验证的真实场景：
若未定位：仍存假设、各自反证、下一条能区分假设的观测：
```

已发布缺陷发现时立即开账、根因明确时立即记账，按 `AGENTS.md` 执行；
不要等模板填完才补写。收口仍按既有工具规则，不以模板代替真实场景验收。

## 数据与保存

```text
字段来源/单位/股票代码/时区/交易日口径：
原始样本 → 解析值 → 队列/业务状态 → 界面结果：
用户配置还是可重建缓存：
提交值 → 实际文件内容 → 新进程读回 → 界面结果：
异常/主备失败/跨日/切股晚回包/损坏恢复的适用场景：
实际执行的正向及负向验证：
真实接口、原始现场和恢复边界中仍未验证的部分：
```

## 界面与性能对照

```text
问题类型/可观察指标：
源码状态、系统、字体/缩放、窗口状态、数据和工具参数：
修改前证据及采样范围：
本次改变的变量：
修改后同条件证据、波动和干扰因素：
结论：保留 / 撤回本次优化 / 暂缓；依据：
证据边界：离屏 / 源码原生 / 安装版；未验证：
```

## 任务交接

```text
目标与本次范围：
分支/HEAD/相关未提交差异（不可只写 HEAD）：
已修改文件与行为：
已执行命令、退出码、结果及原始证据路径：
失败/错误/跳过/flaky（跳过不是通过）：
证据绑定的源码/输入/环境，复用或失效的条件：
首次失败/不稳定结果及后续复测（分别保留）：
尚未执行或未通过的验证：
并行改动/敏感数据/禁止执行的操作：
下一步最小动作：
本任务承诺的判据是否逐项满足（不满足就保留未完成）：
```

只有实际执行过的才写“已验证”；导航输出的命令仍是建议。小任务不必重复长段背景，
引用已有证据即可。任务完成与源码验证、安装版验收、真实用户故障关闭分别表述。
