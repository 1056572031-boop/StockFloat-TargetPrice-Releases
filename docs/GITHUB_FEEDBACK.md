# GitHub 私有诊断反馈

## 决策与边界

2026-10-19，用户明确批准由 `1056572031-boop/Skyrocket-Private-Feedback` 私有仓库保存“自动采集并脱敏后的诊断包＋用户主动填写的描述”，替代 2026-10-17 桌面实施计划中的私有对象存储。这是存储路线变更，不自动授权公开反馈数据、发布应用或把管理员凭据放进客户端。

```text
右键“反馈问题” → 菜单收口后只读采集 → 用户描述（可选）
  → 用户主动点击“上传反馈”（不再另设确认勾选）
  → 后台生成校验包 → 本地持久 outbox
  → Cloudflare Pages Functions 免费 HTTPS 收件入口（专用 GitHub App 凭据只在服务端）
  → GitHub 私有 Release ZIP 附件 → 下载核对原字节 → 回执附件
  → 维护者电脑定时拉取 → 本地 SQLite 队列 → 下载校验
  → 无凭据、禁网络的隔离分析 → 本地 JSON / Markdown 报告
```

包和描述不提交进 Git 历史。普通用户不需要 GitHub 或 Cloudflare 账号；客户端只调用公网入口，不能复用维护者的 `gh` 登录或包含 GitHub token。默认入口为 `https://skyrocket-feedback-1056572031.pages.dev/v1/feedback`，可用 `SF_FEEDBACK_ENDPOINT` 覆盖；空地址或非 HTTPS 地址禁用上传，不显示假成功。

GitHub App 只安装到批准的一个私有反馈仓库，具有内容读写及隐含的元数据读取权限，不授权私有源码、工作流或仓库管理。私钥由本机受保护文件及 Cloudflare 服务端 Secret 保存，不进入客户端、Git 历史或部署日志。部署前重新核对实际安装范围；服务端只申请该反馈仓库的短时安装令牌。

## 采集与同意

- 自动采集仅保留允许的版本、随机进程运行标识、采集时间、错误计数，以及网络/分时/回退状态布尔值。`health=null` 表示没有足够依据作整体健康结论。
- 旧格式仅包含计数和少量标志，不采集日志、完整配置和股票/目标价细节；新完整格式复用“导出诊断包”，发送同范围的脱敏日志、配置、证券与目标提醒状态、系统/窗口/启动/存储现场及崩溃关键片段。密码、令牌和已识别身份字段脱敏；不新增截图、摄像头画面或音视频。
- 描述可空，最多 4000 字；身份路径和已识别的凭据字段脱敏，实际上传文本在内部封存，不再展示“上传内容”或“问题描述”页签。自动脱敏不能保证自由文本没有个人信息。
- 脱敏替换后再次检查长度，超限拒绝生成而非静默裁剪。整数只使用两端均可精确表示的范围；采集越界或超限留痕，不通过舍入伪造数值。
- 编辑描述更新内部脱敏内容；无需勾选，只有主动点击上传才提交。待处理反馈使用原包和原幂等键重试，不重新采集现场。
- 上传绑定当前已生成的脱敏内容，提交直接封存该份内容，不再从原描述重新脱敏。旧待提交包恢复其原始封存内容，不进行二次改写；即使身份信息或脱敏环境随后变化，也不悄悄改变本次提交内容。
- 当前采用维护者按反馈编号人工删除，不承诺自动到期删除或平台备份即时删除。按 2026-10-20 的界面要求，主窗不再显示长段说明、字数计数或确认勾选，接收范围和保留政策未改变。人工处理须分别核对 GitHub 附件、Cloudflare 案件元数据、本机 ZIP、队列和报告；不能只删一个文件就宣称全部删除。后续若更改保留/删除语义，必须更新策略版本，不沿用旧确认。
- “关闭”不是撤回已发送字节。提交中退出后状态在重开界面时恢复为未知，仅用户再次点击才重试；无后台静默重传。
- 未保存草稿仅在本进程保留。形成 outbox 的反馈持久化；原手工“导出诊断包”仍独立可用。
- 界面使用原生 Qt 控件；描述框内回车仍是换行，Tab 可离开输入框。超限、脱敏失败、服务配置或本地包错误继续阻止上传，不因隐藏控件放宽校验。主窗不展示状态说明；上传中、成功和失败由独立小弹窗承载。成功、普通重试、保存结果未知分别显示“已上传”“重试上传”“核对并重试”。不再展示“新建反馈”下拉；重启后自动恢复最早一条待提交反馈，只恢复内容、不自动发送。关闭已成功的窗口后再次从菜单打开，生成新草稿；未上传草稿和进行中上传继续复用原窗口。
- 失败提示区分未保存、已入队和保存结果未知。生成包前失败明确提示草稿未保存；入队/回读结果未知时锁定原草稿和提交标识，重试先查原记录，不重新生成重复包；确认已入队才提示可按原编号重试。`feedback.json` 和本地日志只记录固定失败阶段及允许的错误类别，不记录原始异常正文。可恢复的上传错误不应禁用再次点击；配置、采集或包损坏错误仍阻止提交。

## 收件规则

- 仅批准的私有仓库可用；每次提交/拉取先检查仓库仍为私有。
- 使用专用私有 draft Release `feedback-inbox-v1`，不属于 Skyrocket 应用发行。
- 旧格式ZIP最多256 KiB，保留 `manifest.json`、`state.json`、`problem.txt`；完整格式payload 2最多32 MiB，额外包含原字节 `diagnostics.zip`，使用独立隐私策略版本。完整协议与验收边界见 [FULL_DIAGNOSTIC_FEEDBACK.md](FULL_DIAGNOSTIC_FEEDBACK.md)。
- 本机发送前深度验证完整包和凭据残留，云端轻量核对容器、目录、SHA-256和容量，完整回执明确 `validation_scope=container_sha256_and_member_catalog`；维护者电脑在隔离进程内再次完整解析。收件成功不代表完整内容分析或故障定位完成。
- 生产每日100次提交尝试保护不变；增加每日256 MiB请求体预算和单实例在途内存保护，不增加可绕过额度的测试标记。常规与大包验收在本地执行；正式完整样本工具默认不联网，显式live最多一次POST，结果未知先读回原编号而不自动重复提交。
- 客户端在启用旧包重试、调用任何发送器和发出 HTTPS 前也执行独立上传白名单校验，拒绝额外附件/清单字段、身份不一致、过大的成员和错误信封。读取实际待发字节后再次核对整体哈希，不能把“远端最终拒收”当作“数据没有离开本机”。客户端与 Python 收件适配器共用不含管理凭据的上传协议校验函数。
- `feedback-<幂等键>.zip` 上传并真实下载比对之后，才写 `feedback-<幂等键>.receipt.json`。回执是管理代理的提交标记；只有 ZIP 没有回执的孤儿不能当成收件完成。
- 同键同字节返回原回执；同键不同字节拒绝；回执存在但 ZIP 缺失拒绝；响应丢失保留原包重试。
- 回执不仅绑定包哈希和大小，还必须匹配批准的仓库、当前提交标识对应的案件编号、资产编号类型、同意/保留策略以及含时区的收件时间；已缓存回执也不豁免。其他仓库或别的案件不能被显示为当前 GitHub 反馈已成功。
- 正式入口使用 D1 原子请求计数、案件占位和带随机 token 的租约；旧执行者不得覆盖或释放新租约。同名 GitHub 附件不能覆盖，部分成功只能返回未确认并使用同键恢复。
- 每日最多100次有效入口请求（含重试），案件索引自设1000条熔断；旧格式ZIP最多256 KiB，完整格式最多32 MiB。GitHub单个收件箱还有1000个附件的硬上限，一份反馈通常占ZIP和回执两个名额；写入前按实际附件数检查余位，剩余不超过100时由既有后台轮询合并提醒。容量检查是快照而非并发名额预留，上游拒绝时保留本地包，不假成功或自动付费。D1只存配额、幂等标识、哈希和回执元数据，不存正文或ZIP；这些保护不是DDoS防护或无限容量承诺。
- 使用服务商免费方案及 `pages.dev` 地址，没有购买域名、开通付费计划或启用自动升级。免费额度、CPU 和存储限制由服务商执行，不能把本次有限样本写成不限量 SLA；服务商政策变化须另行复核。
- `/health` 只说明绑定配置是否就绪，不证明上游 GitHub、下载、分析或冻结包已验收。服务错误仅记录阶段和固定错误类别，不记录正文、密钥或签名下载地址。

## 部署入口

正式收件源码位于 `services/feedback-worker/`，ZIP解析和CRC使用固定版本的zip.js，严格JSON解析使用jsonc-parser。正式客户端携带 `Skyrocket-Feedback/1` 标识，但不能把它当成身份凭据。不能把GitHub可信API的仓库元信息误按上传白名单裁剪；API响应仍有读取上限及角色/仓库校验。

```bash
cd services/feedback-worker
npm ci --ignore-scripts --no-fund
npm test
npm run build:pages
node setup-github-app.mjs --directory /private/github-app \
  --worker-url https://example.pages.dev --gh /absolute/path/to/gh
node deploy-pages.mjs --configuration /private/wrangler.pages.production.jsonc \
  --app-configuration /private/github-app/configuration.json \
  --directory /private/cloud-pages --enable
```

授权使用 GitHub 官方 manifest 流程，回调为带防伪状态路径、无查询参数的 `localhost` URL；仓库选择为全部或多于一个时拒绝完成。部署配置中的账号选择不写进 Pages 配置文件，私钥只作为 Secret 上传；保留构建哈希与部署回执。实际账号、数据库 ID、App 私钥及生产配置不随公开源码分发。部署工具不包含任何付费开通接口。

最初的 `workers.dev` 入口在本机 TLS 握手阶段被重置，不能当成可用结果；正式入口改用已经真实试传通过的 `pages.dev`。不要把旧地址或失败日志改写成成功。

`tools/feedback_service.py` 保留为本机或自有 TLS 代理后的收件适配器，不是当前免费生产入口。它只监听回环地址，单进程内串行发布、并发上限 2；不能用其线程锁冒充云端多实例协调。部署时同样不得把本机全仓权限凭据复制到服务器。

```bash
./.venv/bin/python tools/feedback_service.py \
  --gh /absolute/path/to/gh --data-dir /private/receiver-data --port 8769
```

若显式选择自有服务器适配器，TLS 代理转发 `POST /v1/feedback` 到 `127.0.0.1:8769`，独立限制请求体、连接时间及并发。这个选择不自动修改当前正式入口。

管理员初始化和真实合成验证（会向批准的私有仓库写入测试附件）：

```bash
./.venv/bin/python tools/verify_feedback_github.py --initialize \
  --gh /absolute/path/to/gh --out /private/feedback-evidence
```

该工具仅生成合成计数和明确测试描述，不采集用户现场；同时验证远端读回、同键回执和本机隔离分析。不能证明公网 HTTPS、普通用户无管理员权限上传或冻结包已验收。

## 本机管理代理

```bash
./.venv/bin/python tools/feedback_agent.py \
  --gh /absolute/path/to/gh --data-dir /private/feedback-agent/data
./.venv/bin/python tools/install_feedback_agent.py \
  --gh /absolute/path/to/gh --destination /private/feedback-agent --activate
```

安装工具复制哈希绑定的独立源码快照，固定仓库外的 Python 3.14.7 基础解释器及 `gh` 绝对路径，生成 `com.skyrocket.feedback-agent` LaunchAgent，每 1800 秒（30 分钟）执行一次；用户登录或重新加载启动项时先执行一次。它不依赖开发工作树、shell 激活或 PATH；不会静默覆盖不同的既有 LaunchAgent。基础解释器/gh 被删除或 GitHub 登录失效仍会失败，日志和退出码必须保留。30 分钟不是到达时限承诺，离线、休眠和限流可能延迟处理。

当前安装入口使用版本化代理的 `--desktop-dir`，把已验证的JSON、Markdown及原始反馈ZIP一起保存到桌面“Skyrocket 用户反馈报告”的案件目录。原包不重复下载、不自动解压执行，不覆盖用户编辑；单案异常继续处理其他案件，导出失败参与同一次状态提醒。独立解释器禁用用户站点包，不依赖工作树之外的未固定Python扩展。

每轮完整分页并先持久化新案件，再处理队列；下载/分析失败留在重试队列。进程锁阻止两个本机代理同时处理。坏回执、本地坏记录和缓存损坏按案失败，不得阻塞其他案件；下一轮重新发现失败案件并恢复。下载核对哈希和大小，报告校验真实落盘并保存报告文件哈希。重启后不复用损坏报告，规则或分析器版本变化时重新分析，原报告按独立运行编号保留。失败案件不因“游标已推进”而漏掉。

复用完成结果前，同时核对原始 ZIP 的存在、大小和哈希、报告绑定的 ZIP 哈希、两个报告文件的路径和哈希，以及分析器与规则版本。缺包、错包、缺报告或缓存绑定不一致时重新下载分析，不沿用“已完成”。案件编号必须符合固定格式；数据目录内的对象、报告、数据库及其辅助文件、进程锁和通知状态/通知锁禁止经符号链接重定向。异常本地案件只记录固定错误类别，不回显不可信编号。这些检查防止既存异常路径和损坏缓存，不宣称能抵御拥有同一账户权限的进程并发替换目录。

反馈窗口与主窗口共用 `GlassMixin` 和同一背景绘制入口，跟随主窗口实际使用的 Liquid Glass、旧版玻璃或降级背景，而不是单独模拟透明色。输入区使用低透明度背景，不遮住材质；共用圆角、明暗和边缘规则。无边框标题区可拖动，右下角保留调整大小的手柄。隐藏/关闭时移除嵌入的原生材质，重开重新建立，不创建独立背景窗口，也不取消后台上传或清空未提交草稿。源码像素、原生组件与正式安装客户端分别验收。

分析进程清空凭据环境，使用 macOS sandbox 禁止网络、Keychain/gh/SSH 凭据读取及输出目录外写入，并限制 CPU、文件大小、描述符和总耗时。隔离不可用时失败，不降级为无隔离执行；没有声称这是任意代码执行沙箱，上传内容始终只作为数据读取。

`suspected_problem` 表示当前快照出现健康异常或运行状态告警；历史错误计数单独出现时为
`insufficient_evidence`，因为无法确认发生时间、是否恢复或与本次反馈的关系。
`_secret_keys_dropped` 是隐私过滤数量，仅作为 `privacy_filter` 说明项，不触发故障结论。
`no_known_issue` 只是现有规则未检出；未知健康状态仍为证据不足，不因隐私过滤正常而判定整体健康。
报告保留计数值、清单中的应用版本/会话/采集时间、缺省和截断范围以及可用的当前运行标志；
`machine` 是分析器机器架构，不是用户设备。描述中的测试声明只作不可信提示，所有案件默认
`sample_classification=unverified`，不按描述关键词自动排除或计入已确认真实用户故障。
测试归档和用户故障统计需人工核对独立来源；默认规则不自动产生“确认缺陷”、修复、发布或关闭结论，
视觉问题仍需独立取证。分析器升级使旧缓存失效，重分析生成独立新报告，不覆盖旧报告。

## 本机主动提醒

独立管理快照包含 `sf_feedback_notifications.py`，通过 macOS 自带的 `osascript` 发送系统通知，不引入付费服务或第三方常驻软件。新报告合并为数量提醒；后台登录、收件或分析失败时提醒，持续相同失败状态不每轮重复打扰，恢复后提醒一次。重新分析产生的新报告也可提醒，不等于新增用户反馈。

通知不包含用户描述、诊断正文、凭据或签名下载链接。消息作为独立参数传递，不拼接进脚本源码。报告判断来自本机持久队列，通知调用失败后不会消耗事件，下轮即使报告已被分析缓存仍会重试。`notifications.json` 保存报告运行标识和失败指纹，独立文件锁避免重复进程同时发送；最多保留当前批次 1000 个报告标识。

通知状态损坏或不可写时不静默清空历史，返回非零并保留故障记录，不妨碍已下载的包与报告落盘。系统通知提交后若去重状态落盘失败，下一轮可能重复提醒，不承诺跨系统通知与本机文件的严格一次送达。通知权限、系统通知设置和专注模式可能影响实际展示；命令退出 0 只证明系统调用接受，不证明用户已看见。通知通道本身不可用时仍须查看运行日志，不能承诺通过同一个失效通道提醒它自己的故障。

首次迁移仅将已核对的历史合成样本记为已通知，不将未核对的新反馈吞掉；不覆盖现有通知状态。实际安装/发送证据与后续真实用户验收分开保存。

## 公开源码兼容

隐私扫描只识别上述明确批准的反馈仓库完整名字和 HTTPS 域名，不豁免裸账号、相似仓库、仿冒域名或其他个人联系方式。原始字节上的凭据、声明的密钥和用户目录检查保留；合法地址旁混入敏感信息也必须拒绝。服务端的 PEM 格式标记由固定片段组成，真实完整私钥标记仍触发扫描；不得跳过历史对象检查。测试对实际反馈模块、管理工具、用例和服务端源码执行相同扫描函数。

## 验证范围
