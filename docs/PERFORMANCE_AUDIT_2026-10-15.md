# Skyrocket 全模块性能专项

日期：2026-10-15，Asia/Shanghai。工作区版本：1.4.88，本轮未安装、未发布。

## 范围

本轮覆盖根目录全部 50 个产品 Python 模块的职责、调用频率和资源边界。
“全部模块审查”不等于“每个模块都改过或都变快了”。实际产品优化集中在
`sf_ui_render.py` 与 `sf_universe.py`；不改变行情轮询、动画帧率、数据时效、
目标价、摄像头策略、网络安全、原子持久化和更新事务。

开始时已经有渲染圆角、手动刷新、分时日期、存储、窗口控制器、安装/签名、
更新说明等未提交改动，过程中还有并行编辑。它们全部保留，不计为本轮性能成果。
前后微基准的 50 模块 SHA256 对账只发现上述两个产品模块变化。
之后的最终复测期间已有其他专项继续修改网络/隐私等模块；不能把后续整仓状态
当成原始对照快照，也不能用一次回归的结果替代对最新文件的验收。

## 实施内容

1. 分时折线与填充共用价格路径；填充封口和渐变按数据版本、点数、首末价、
   昨收引起的范围、趋势色、绘制区域及透明度失效。每窗口只保留最后一份缓存。
2. 旧玻璃内侧超椭圆按尺寸、内缩、半径复用；颜色和系统外观仍实时读取。
   新玻璃圆弧算法、圆角门禁不改。
3. 底部双行布局按文本、颜色、宽度、字体度量、间距和布局算法复用。
   数据或布局变化立即失效，不改变缩号与不越界规则。
4. 本地唯一包含搜索遇到第二条命中就交还联网排序；模糊救场到请求上限即停止
   收集，保持前缀优先及原索引顺序。零、负、None limit 保持切片语义；返回副本。
   代码段资格查询不再复制整张代码表。
5. 修复功耗探针的过期模拟数据：完整字段、源时间、ISO 来源日期与成交量单位
   必须经过真实解析器。只复制几何配置，清除守卫、目标价与私有接口，
   隔离图标、更新、日历预热、清理和重开回调，不触发真实业务。

旧探针首次运行触发熔断并沿用真实守卫配置，该结果已排除，不用于提升结论。

## 验证

- 新增专项 18 条，连同既有缓存、版本、搜索、底部专项，最终共 64 条通过。
- 冻结旧几何、强制每帧重建路径、恢复全表扫描三处种错均被拒绝。
- 首次性能改动后静态闸门通过，A 级硬零，未提高任何基线。
- 两个改动模块都在既有诊断导出闭包内；未新增独立业务状态或诊断盲区。
- `verify_card_corners.py --native` 源码层 PASS。旧/新两代玻璃均完成白底原生截图、
  四角越界、拖动、收展、最小化恢复走查。未传 `--app`，不能当作包内同源证据。
- 原生 Cocoa 窗口约 60.7 帧/秒、行情约 9.7 次/秒；窗口可见、首帧已画、
  `probe_valid=true`、`poll_fail=0`，标准错误为空，见 `power-after-native.json`。
- 独立离屏最终复测约 61.8 帧/秒、行情约 9.6 次/秒；盘后只画了初始一帧。
  均有有效行情及分时数据，失败计数为 0。
- 进程单核 CPU 短样本：盘中对照 14.23%，最终复测 15.42%；盘后对照 2.30%，
  最终复测 3.06%。它们包含初始绘制/加载，期间有系统与并行任务负载差异，
  **不能据此宣称整体 CPU 或耗电下降**，也不能将局部基准百分比外推到整机。

## 证据与边界

`outputs/performance-20261015/` 保存 `before.json`、`after.json`、前后 PNG、
事件循环 JSON/标准错误与 `mutation-checks.log`。微基准只支持所列路径，
不能表述为“全程序快 42%”或“省电 42%”。

本轮未更换装机包。真实网络延迟、GPU/WindowServer、续航、长期内存泄漏、摄像头
实测，以及锁屏/休眠/多屏矩阵不是离屏基准可以证明的，需独立长稳与实机补证。
新版本仍须通过完整发布链，包括包内特征、原生圆角截图、安装/OTA 和公开资料。
