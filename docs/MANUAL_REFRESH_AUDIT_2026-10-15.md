# 刷新行情专项走查（2026-10-15）

## 结论与交付边界

- 右键菜单、macOS 菜单/窗口快捷键的文案均由「立即刷新」改为「刷新行情」，保留图标及 Ctrl+R 的平台映射。
- 确认并修复一处并发缺陷：行情与分时共用调度 Event，其中一个线程清除事件后，尚在处理请求或尚未进入等待的另一个线程会丢失通知，最长再等一个调度睡眠周期（常规封顶 5 秒）。
- 改为各自独立的 Event，并在调度变更和退出时唤醒两者。保留共享事件作为非循环调用/轻量宿主兼容路径；不改变自动轮询频率、网络超时、行情字段或目标价规则。
- 本轮仅修改源码与验证资料，没有升级版本、打包、替换 /Applications、发布 OTA 或提交推送。源码当前版本仍为 1.4.88，后续发版必须提升版本号，不覆盖已发布资产。

## 路径走查

| 环节 | 路径与验证结果 |
| --- | --- |
| 右键入口 | FloatWindow.contextMenuEvent 创建可用的「刷新行情」action，绑定 _force_fetch；触发一次只分发一次。 |
| 原生入口 | sf_macos_menu.install_window_actions 同名 action 复用 _force_fetch，保留快捷键。 |
| 请求合并 | _force_lock 保护行情与分时两个待消费标志；连续 100 次请求合并，不为每次点击建线程。 |
| 双路唤醒 | _quote_resched / _minute_resched 各自消费；其中一个已清事件不影响另一条。旧实现确定性复现失败，新实现通过同一判据。 |
| 在途请求 | 不取消正在执行的网络请求；刷新标志保留，完成后补拉。行情请求受阻不阻塞分时刷新。 |
| 调度 | 强制标志绕过常规到期/长暂停退避，sched.mark 更新本次请求时点，避免到期逻辑再补一轮。 |
| 死线程恢复 | _force_fetch 重建并登记常驻 wrapper；存活时不额外建线程。 |
| 主源与备源 | 行情腾讯失败可切新浪；分时腾讯失败可切东财。备源成功不等于主源健康，保留原有诊断与熔断口径。 |
| 数据新鲜度 | ensure_current_quote 校验源时间；旧数据、未来时间、缺失时间均有拒绝/备源用例，不伪造新时间。 |
| 切股与迟到回包 | _fetch_quote / _fetch_minute 冻结请求代码，_poll 按代码拒绝旧股票回包；美股代码也有既有回归覆盖。 |
| 队列与线程边界 | _q_put 有界入队并发 Qt 信号；_poll 在 GUI 线程消费。目标价极值缓冲独立于可丢弃的显示帧，队列溢出不漏已收到的越线价。 |
| 失败与恢复 | 坏数据和网络异常沿用失败计数、日志限流、熔断；行情连续失败达到 3 次才上报网络异常，恢复真数据后清除。分时失败保留当日曲线并标滞。 |
| 生命周期 | 退出后拒绝刷新、不重建线程；退出唤醒两条长睡线程并 join。 |
| 显示 | offscreen 像素用例通过；cocoa 平台真实 QMenu 抓帧确认文案、图标和菜单顺序，无重叠/截断。 |

## 四层验证

### 数据取得

北京时间 2026-10-15 10:06:38 发起独立网络抽样，标的 sh600519：

- 行情：腾讯，源时间 10:06:32，price=1307.02、pct=1.63，新鲜度校验通过，耗时约 0.107 秒。
- 分时：腾讯主源出现 HTTP 501，东财备源成功返回 37 个点，覆盖 09:30 至 10:06，耗时约 1.203 秒。
- 更早一轮分时主备均失败（HTTP 501 / RemoteDisconnected），后续抽样恢复，不能将其归因为本次代码修改。
- 行情和分时是分开采样，不要求两个接口的末价完全相同。以上只是单标的一次成功抽样，不构成全市场或长期可用率证明。

### 实现正确性

- 新增真实线程验证：双路唤醒不相互吞通知、在途后补刷、连点合并、死亡恢复、退出后拒绝，以及退出唤醒并回收长睡线程。
- 新增菜单回调/快捷键验证与完整 UI 链路：真实菜单 action → 两条真实循环 → 注入网络响应 → 有界队列/Qt 信号 → 窗口价格和分时更新。
- UI 链路用例明确使用受控数据，不以模拟响应冒充线上数据验证。
- 沿用相关调度、行情新鲜度、旧回包、队列越线保护、分钟重试、窗口生命周期回归。

### 表达一致性

- 两处用户可见菜单统一为「刷新行情」；历史交付记录不追改。
- 注释明确「唤醒后拉取，在途请求先完成」，移除无条件「最多 100ms 消费」的过度承诺。
- 菜单模块无独立业务状态，已在 diag_coverage.txt 当前版本段说明诊断边界；实际线程存活与网络故障继续走既有导出通路。

## 保留的行为边界

- 「刷新行情」包含最新报价和分时，不是让上游生成一笔新成交；休市或无成交时数值不变属于正常结果。
- 网络请求不是立即完成；正在执行的请求不会被本次点击取消，等待时间受网络超时与备源路径影响。
- 菜单没有新增进度、完成气泡或单次失败弹窗。沿用连续失败阈值，单次失败可能没有立即可见反馈；这属于既有交互边界，不宣称本轮已新增反馈。
- 原生菜单已用 QAction 触发与快捷键配置验证，但未用系统级键盘事件注入验证 Cmd+R 的实际按键路由。
